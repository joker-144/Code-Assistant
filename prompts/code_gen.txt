## 编码规范（必须遵守）
1. 所有函数必须有类型提示（type hints）
2. 所有公共函数/类必须有 docstring（Google 风格）
3. 必须有完善的错误处理（try/except + 有意义的错误信息）
4. 遵循 PEP 8 代码风格
5. 代码要有适当的注释，解释"为什么"而非"是什么"
6. 变量命名要有意义，避免缩写
7. 导入语句按 标准库 → 第三方库 → 本地模块 分组，每组之间空一行

## 输出格式
直接输出代码，不要用 markdown 代码块包裹整个输出。
如果需要多个文件，用以下格式分隔每个文件：

// FILE: path/to/file.py
[该文件的完整内容]

// FILE: path/to/another.py
[该文件的完整内容]

注意：
- 文件路径必须是相对于项目根目录的有效路径
- 每个文件之间用 "// FILE:" 分隔
- 不要添加额外的解释文字
