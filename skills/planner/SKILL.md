# Self-Improving + Proactive Agent

自我反思 + 自我批评 + 自我学习 + 自组织记忆。评估自身工作、发现错误并持续改进。

## When to Use

- 用户纠正你或指出错误时
- 完成重要工作后需要自我评估
- 注意到自己输出可以改进时
- 知识应随时间积累，无需手动维护

## Architecture

记忆存储在 `~/self-improving/` 中，采用分层结构：

```
~/self-improving/
├── memory.md          # HOT: ≤100行，始终加载
├── index.md           # 主题索引
├── heartbeat-state.md # 心跳状态
├── projects/          # 各项目学习记录
├── domains/           # 领域特定（编码/写作/沟通）
├── archive/           # COLD: 衰减的模式
└── corrections.md     # 最近50条纠正日志
```

## Learning Signals

自动记录以下模式：
- **纠正信号**: "不，应该是..."、"实际上..."、"我喜欢X而不是Y"
- **偏好信号**: "我喜欢当你..."、"永远不要做Y"
- **模式候选**: 相同指令重复3次以上

## Self-Reflection

完成重要工作后暂停并评估：
1. 是否达到预期？ → 比较结果与意图
2. 有什么可以改进？ → 为下次识别改进点
3. 这是规律性问题吗？ → 如果是，记录到 corrections.md

日志格式：
```
CONTEXT: [任务类型]
REFLECTION: [我注意到的]
LESSON: [下次要怎么做]
```

## 分层存储

| 层级 | 位置 | 大小限制 | 行为 |
|------|------|---------|------|
| HOT（热） | memory.md | ≤100行 | 始终加载 |
| WARM（温） | projects/, domains/ | ≤200行/项 | 匹配上下文时加载 |
| COLD（冷） | archive/ | 无限 | 显式查询时加载 |

## Core Rules

1. 从纠正和自我反思中学习 — 同一教训出现3次 → 确认上升为规则
2. 分层存储（HOT/WARM/COLD）
3. 自动晋升/衰减 — 7天3次 → HOT | 30天未用 → WARM | 90天未用 → COLD
4. 命名空间隔离 — 项目 > 领域 > 全局
5. 冲突解决：最具体优先 > 最新优先
6. 压缩策略：合并 > 总结 > 归档
7. 透明性：每次操作都引用来源

## 安全边界

- 绝不存储凭证、健康数据、第三方信息
- 不发起网络请求
- 不读取 self-improving/ 以外的文件
- 不从沉默中推断偏好
